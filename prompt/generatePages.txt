Create or update Playwright Page Object Model classes and custom fixtures for this repository.

Repository context:
- Playwright + TypeScript test framework.
- UI tests are under tests/ui.
- Page objects belong under pages/.
- Custom Playwright fixtures belong under fixtures/.
- Use @playwright/test and existing repository conventions.

Before editing:
1. Read the target UI spec and nearby UI tests.
2. Identify each distinct application screen or responsibility from the actual flow.
3. Inspect existing selectors, waits, assertions, and fixture patterns.
4. State one local hypothesis about the refactor and one focused validation check.

Implementation rules:
- Create one page class per meaningful screen or responsibility.
- Page objects own locators and reusable interactions only.
- Keep test data, generated values, scenario order, and all assertions in the spec.
- Create custom fixtures with test.extend().
- Every page-object fixture must create a fresh instance from the test's built-in page fixture for isolation.
- Use a single login(email, password) method that includes filling credentials and clicking Sign In; do not create a separate clickSignIn method.
- When an address form has multiple fields, expose one fillAddressForm(address) method with a typed address object.
- Preserve existing waits, assertion expressions, assertion wording, and assertion locations unless the user explicitly asks for changes.
- Do not silently change selectors, test behavior, authentication, data generation, or other tests.
- Prefer existing locators and APIs over new abstractions.
- Keep methods concise and typed. Do not place expect() assertions inside page objects.

Spec refactor rules:
- Import test and expect from the custom fixture module.
- Replace direct locator interactions with page-object method calls.
- Preserve the existing test flow and assertion variables where practical.
- Keep assertions in the spec, including text-content assertions.

Validation:
1. Run the narrowest relevant Playwright test, preferably with --project=ui-tests.
2. Run npx playwright test --list to catch fixture/import/discovery errors.
3. Run the repository's available TypeScript check if configured.
4. Report any pre-existing failures separately from failures caused by the change.

Requested change:
Describe the target UI spec or flow here, including its path and any page responsibilities that should be covered.

Use the target spec and nearby tests as the source of truth. Infer page objects only from the actual flow, explain the responsibility of each page file and fixture change, and preserve the existing behavior unless explicitly asked otherwise.
